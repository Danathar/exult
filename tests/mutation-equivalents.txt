# Surviving mutants a reviewer has judged harmless.
#
# tests/mutate_changed.py makes small edits to the lines a branch changes in
# product files the unit tests build - a comparison flipped, `&&` swapped with
# `||`, an `if` forced true or false, a statement dropped - and rebuilds and
# runs the unit tests after each one. An edit every test still passes with is
# a survivor, and the check fails on any survivor that is not listed here.
#
# List a survivor only when no test should fail on it:
#
# - equivalent: the edit cannot change what the code returns or opens
# - message-only: it changes only the wording of a warning or log line
# - untestable here: the difference needs a condition the unit tests cannot
#   set up (say why)
#
# A survivor that changes which file is found, or whether one is, needs a test
# instead.
#
# Each entry is a block of six lines, and blank lines separate entries. The
# check prints every unlisted survivor in this form with `reason:` empty; copy
# the block here and write the reason after it.
#
#   file: the path of the mutated file, from the repository root
#   line: the line number of the edit, for the reader only
#   after: the nearest non-blank line above it, stripped
#   original: the source line the edit replaces, stripped
#   mutant: the source line after the edit, stripped
#   reason: one line saying why no test should fail on it
#
# An entry matches on file, after, original and mutant together. The line
# number is not part of the match, so an entry still matches after lines above
# it move; `after` keeps an entry for a common line such as `return false;`
# from excusing the same edit somewhere else.
